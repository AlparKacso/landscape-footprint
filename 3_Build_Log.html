How this was built

Not in one sitting. The eight hours ran across six days in five or six short sessions, and that matters to what came out: almost every removal in this log happened because I left the prototype alone and came back to it. Living with a feature for ten minutes settles arguments that reasoning about it does not, and coming back the next day settles more.

I also did not build one prototype. I built three, and the third is a deliberate merge of the first two.

Roughly 60% of V1, a little of V2, and a lot of subtraction. V1 as the underlying model, stripped and enhanced until it was explainable in a seven-minute pitch.
The rule I cut against. Every keep / drop / add decision was scored on one question: does this help the customer take the decision? Not "is it clever", not "was it hard to build". That rule is why a working risk engine came out and a four-state evidence model stayed in — and it is the reason the shipped version is smaller than the one I had at hour three.

The honest version of the AI story is here rather than in a claim about tooling. Working with an agent produced depth quickly, and the depth was real — but it also produced a decision model with more moving parts than the problem needs. The work that mattered was the stripping: pulling the logic back until it was defensible, explainable and still worth something. That judgement is not something the agent supplied, and it is most of what the second and third passes were.

What I built

  • A Context Slice page — where a customer loads their own four files and sees what the extract can and cannot support. Files are matched to adapters by column signature, not filename, because a Basis team exports ZOBJ_DUMP_PRD1_0714.CSV, never objects.csv. Load, the boundary between what is computed and what a model wrote, coverage, and scope.
  • A rules engine, not a model. Twelve ordered rules decide, first match wins, and every weight they read sits in one editable rulepack file — so "why does it say retire?" is answered with a named rule and rows from the customer's own extract. Five calls: Remediate Investigate Workshop Retire Carry as-is.
  • A four-state evidence model — the spine. Measured and running, measured at zero, never measured, and cannot be measured, because tables have no execution counts. Only the first two are observations.
  • The Landscape Footprint — Position first, drawn as a treemap of the eleven decisions sized by object count and coloured by call; then Scope; then the decisions. Each decision opens a modal with its objects, its blast radius as a graph, and an editable call.
  • One control that changes the answer — the transition type, reading the same evidence as no-path, brownfield, greenfield or selective. It does not only reorder: where the route genuinely changes what you would do, it changes the call and shows the sentence why. Seven of forty-four route/decision combinations move.
  • A Discovery Agent on both pages — named for the vision paper's first agent type. It explains the page at the register you pick: for the board, the programme, the engineer. Composed from live numbers every time it opens rather than cached, so it cannot describe a position the page is not showing, and marked as model-written wherever it appears.
  • A verification harness that re-derives every headline number from the raw files and fails loudly on drift.

What the data changed about the design

  • I profiled all four files before designing anything. The shape came from the data, not from a guess about what would look good.
  • The finding that reframed everything: 207 objects have no usage row, which reads as fatal until you split it. 61% of SAP's own standard code is unmeasured against 16% of the custom code, and every object measured at zero is custom. The blind spot sits almost entirely in code nobody was deciding about.
  • Three transaction codes point at programs the inventory does not contain — one labelled "Legacy pricing tool (decommissioned?)", another "Temporary fix 2014". The third runs 3,860 times a month across 74 users. People can run these today; nobody can say who owns them.
  • SAP's own code never calls custom code — not once across 326 dependencies. Retiring custom code will not break SAP; what stops you is people using it, which is far easier to check.
  • I rejected the obvious dead-code test. Nothing uses it, it uses nothing, no usage row — that returns 105 objects, and 101 of them are SAP's. Everything scores on converging signals instead.
  • The evidence basis is load-bearing, not descriptive. Retire is reachable only from a rule resting on a structural fact or an actual measurement. Anything built on inference or a missing record proposes Investigate and names what would settle it. The engine throws on start-up if a rule breaks that.
A number worth stating carefully. It is tempting to say "52 of 106 custom objects run zero times a month". That is three findings wearing one coat: 17 are measured at zero, 17 were never measured at all, and 18 are tables, which cannot carry an execution count by construction. Collapsing them is the fastest route to a confident, wrong retirement list — which is why the evidence model has four states and not two.

Bugs worth recording

  • A split cache, twice, on the deployed copy only. GitHub Pages caches every file for ten minutes independently. A visitor held a new index.html beside a stale app.js, which died on boot — and the error handler blamed the local server, the one thing that was fine. Versioning the <script> tag only busted the entry, so it happened again with a stale sibling module. Fixed properly with an import map pinning all twelve modules plus the entry, and bump.mjs to rewrite all thirteen numbers at once.
  • The sharper half of the same bug. The data files were unversioned too, and a stale rulepack.json beside new code would have produced scores from yesterday's weights — wrong rather than merely old, and silently. They now fetch with cache: 'no-cache'.
  • The treemap rendered blank on first view. It measures its container, which has no box while the page is hidden, and a ResizeObserver does not fire for a display:none → visible transition. Reading the width synchronously after the page is shown forces layout and returns the real number.
  • Controls that rebuilt themselves on every render — the settings panel, then the transition control — detached the button under the cursor, so clicking an option looked like it had done nothing. Built once now; only the selected state moves.
  • Sorting by call opened backwards, putting Carry-as-is above Remediate. Ranked columns now open most-urgent-first.

What the cap counts. Producing the artifact. Reading it back and rehearsing the pitch are not counted — that thinking does not stop, cannot be timeboxed, and changes nothing a reviewer will open. The line is whether the file changes: any correction that lands in the repository gets its own row above, even where that pushes the total past eight hours. A log that admits going over is worth more than one that lands suspiciously exactly on the cap.
Two hours and forty minutes over, and where they went. All of it after the cap, all of it found by rehearsing rather than by building. Reading the scoping back surfaced the one gap the artifact could not see: these four files cannot record a modification or an enhancement to SAP standard, so 106 is every custom object in this extract rather than the system's whole custom footprint. Reordering the Footprint for the walkthrough, and giving three Scope cards the picture behind the number instead of an assertion, took forty. Ten closed an ownership leak the same reading found — four rules missing an isCustom guard, so eight SAP objects carried a call the customer cannot take on code they do not own. Ten gave the transition path's priorities a verb and a direction, because Deferred reads as a status and a Head of Transformation needs an instruction. Ten stopped a Discovery Agent sentence asserting a trigger mechanism no column records. And the last eighty minutes cut the Extract Wizard, which was the largest single removal in the project and the one most consistent with everything else in this table.

Reading the artifact back was free; changing it was not, so all of it is counted. The total says 10h 40m against an 8h cap — and the honest reading of that number is that the last two hours removed more than they added.
What the split says. Nearly a third of the budget went to planning, validating and pivoting rather than building — including the decision to throw most of V1's decision model away. On a challenge with a hard cap that is the uncomfortable allocation, and it is the one I would make again: the build was fast, and choosing what not to ship was the expensive part.

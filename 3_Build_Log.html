What I built

  • An Extract Wizard — a page where a customer loads their own four files and watches what happens to them. Files are matched to adapters by column signature, not filename, because a Basis team exports ZOBJ_DUMP_PRD1_0714.CSV, never objects.csv. Three visible steps: load (where each file is identified and mapped as it arrives), watch the scoring, see exactly where AI is involved.
  • A rules engine, not a model. Every score and every call comes from one editable rulepack file, so “why does it say retire?” is answered with a named rule and rows from the customer’s own extract. Five calls: Remediate Investigate Workshop Retire Carry as-is. An LLM writes the summary sentences and nothing else.
  • A four-state evidence model — the spine of the whole thing. Measured and running, measured at zero, never measured, and cannot be measured, because tables have no execution counts. Only the first two are observations.
  • The Landscape Footprint — Position first, drawn as a treemap of the eleven decisions sized by object count and coloured by call; then Scope; then the decisions and the object inventory on two tabs. Empty until the wizard has been run once.
  • One control that changes the answer — the transition type, reading the same evidence as no-path, brownfield, greenfield or selective. It does not only reorder: where the route genuinely changes what you would do, it changes the call and shows the sentence that justifies the change.
  • A Discovery Agent on both pages, behind one button — named for the vision paper's first agent type, working in the phase it names first. It explains what the page in front of you is saying, at the register you pick — for the board, for the programme, for the engineer. Composed from live numbers every time it opens rather than cached, so it cannot describe a position the page is not showing, and marked as model-written wherever it appears.
  • A human override on every call, with the rule’s original proposal kept beside it and a one-click reset.
  • A verification harness that re-derives every headline number from the raw files and fails loudly on drift.

What I tried & what I learned from the data

  • Profiled all four files before designing anything. That is where the shape came from, rather than from a guess about what would look good.
  • The finding that reframed everything: 207 objects have no usage row, which reads as fatal until you split it. 61% of SAP’s own standard code is unmeasured against 16% of the custom code, and every object measured at zero is custom. The blind spot sits almost entirely in code nobody was deciding about.
  • Three transaction codes point at programs the inventory does not contain — one labelled “Legacy pricing tool (decommissioned?)”, another “Temporary fix 2014”. The third runs 3,860 times a month across 74 users and holds the most recent execution date in the whole extract. People can run these today; nobody can say who owns them.
  • Two vendor scorecards are both live, each with its own transaction code, at 1,229 and 2,515 runs a month. Somebody built a replacement and the original never left.
  • SAP’s own code never calls custom code — not once across 326 dependencies. Retiring custom code will not break SAP; what stops you is people using it, which is a far easier thing to check.
  • Rejected the obvious dead-code test. Nothing uses it, it uses nothing, no usage row — that returns 105 objects, and 101 of them are SAP’s. Confidently useless. Everything scores on converging signals instead.
  • Made the evidence basis load-bearing rather than descriptive. Retire is reachable only from a rule resting on a structural fact or an actual measurement; anything built on inference or on a missing record proposes Investigate and names what would settle it. The engine throws on start-up if a rule breaks that, so a live edit cannot quietly lose it.
A number worth stating carefully. It is tempting to say “52 of 106 custom objects run zero times a month”. That is three different findings wearing one coat: 17 are measured at zero, 17 were never measured at all, and 18 are tables, which cannot carry an execution count by construction. Collapsing them is the fastest route to a confident, wrong retirement list — which is exactly why the evidence model has four states and not two.

What failed / what I cut (and why)

  • Cut: a force-directed graph of the full dependency network. 366 nodes and 326 edges looks impressive and decides nothing — and it is the category the Celonis vision paper spends four pages distinguishing itself from. The graph survives only inside a single decision, answering one question: if we act on this, what else moves?
  • Cut: effort and cost estimates in days or euros. The extract carries no size, complexity or line-count signal, so any figure would be invented — and one invented number undermines every real one on the same screen. It is an explicit Next item once source code is in scope.
  • Cut, then reversed: file upload. Dropped early, on the argument that the adapter seam proves composability without a drop zone. Using the prototype showed that was right in principle and wrong in practice: the seam is invisible, and a customer cannot be asked to trust a pipeline they never see run. It came back as an entire page.
  • Cut: a charting library. A twenty-box diagram does not need one, and a hand-drawn layout renders identically every time — repeatability beats physics when you are presenting live.
  • Failed: sorting by call opened backwards, putting Carry-as-is above Remediate. Ranked columns now open most-urgent-first, size columns largest-first.
  • Failed, then cut on purpose: the risk score. It was computed and never shown, so reweighting a signal appeared to do nothing — found by rehearsing a live modification against the clock. The first fix was to display it. The better fix, made later, was to take it off the screen for good: “risk 72” buys a question that costs five minutes of a ten-minute demo and lands on facts the rule’s own rationale already states in sentences. The score still orders the rows; it no longer makes claims.
  • Failed: the transition control rebuilt itself on every render, detaching the button under the cursor — the same mistake the settings panel made, in a new place. Built once, and only the selected state moves now.
  • Failed: the treemap rendered blank on first view. It measures its container, which has no box at all while the page is hidden, and a ResizeObserver does not fire for a display:none → visible transition — there was nothing to observe. Reading the width synchronously right after the page is shown forces layout and returns the real number.
  • Failed: the settings panel closed on every change — clicking an option re-rendered the panel and destroyed the element under the cursor. Separately, a cached script could make a correct live edit look like it had done nothing, which would have been an ugly moment in front of an interviewer. Both fixed.
  • Merged the mapping step into the load step. Files are matched to adapters by column signature the moment they arrive — the mapping is not a judgement anyone makes, so a whole screen asking them to confirm it was ceremony. The override that mattered moved onto the file row: every file shows what it matched on and what it will be used as, and either can be changed in place. Four steps became three.
  • Rebuilt the scoring step around one picture. It was three stat cards and a rules table running off the bottom of the step — every number present, no sense of how any of them followed from the others. It is now a four-stage strip walking the same 106 objects through evidence, rule, confidence and call, and the derivation is visible in the figures themselves: confidence High 87 is exactly structural 21 plus measured 66. Two real objects are then walked end to end, one reaching Retire on a measurement and one reaching Investigate on an absence, which is the whole argument in two rows. The eleven named rules fold into the stage they belong to behind a see all disclosure rather than sitting underneath as a section — still one click from the whole rulepack, and no longer the tallest thing on the step. 906px to 526px, showing more rather than less.
  • Failed: the pipeline strip rendered at double height. Four stage cards in a four-column grid — except the three arrows between them are grid items too, so seven children wrapped onto two rows. Caught by measuring the step rather than looking at it.
  • Cut: a “less / medium / more” detail slider on the assistant, which was the original idea. Nobody knows which verbosity they are. Replaced with audience — for the board / the programme / the engineer — which is a question anyone can answer in the moment, and which hands you a slide sentence on demand.
  • Rejected: a live API call from the assistant. Same reasoning as the cached decision narrative, plus a sharper one: a cached summary sitting next to a position that moves with the route lever would have contradicted the page the first time anyone switched to greenfield. Composing it from live state at open time solves both, and keeps “no numbers written by a model” literally true.
  • Deferred visual polish. The brief says it is not graded, so the budget went to the decision logic and to keeping the thing genuinely modifiable live — every weight and threshold sits in one readable file.

The second pass, and what it cost

The first build worked and was too big to pitch. Demoing it made that obvious in a way that reading it did not: every question a listener asked was about the machinery rather than the estate. So there was a second pass, and it was mostly subtraction.

  • Removed the risk dial and everything that served it — commitment thresholds, held-versus-committed state, the “what it would take to commit the rest” line. Nobody in a steering meeting says “I accept a risk score of seventy”, and a dial that can be turned up until the tool recommends deleting unmeasured code is not a safeguard. What it protected became a property of the engine instead: nothing is retired on evidence weaker than a measurement, asserted at run time. The two rules that sat behind the dial now propose Investigate, which is what their own rationale text always said. The default output is identical — 24 actionable, 34 held — so nothing was traded away for the simplification.
  • Removed the usage-evidence switch from the interface. It is a question for the customer’s team, not a control for a reader to guess at. It stays in the rulepack, and the assumption is stated on the face of the output.
  • Removed the card view (the list already worked, and the modal carried the prose) and the risk score from the object rows.
  • Promoted the transition type from a hidden setting to the one control on the page, and made it consequential: it now changes the call where the route genuinely changes what you would do, with the justifying sentence attached. Seven of forty-four route/decision combinations move. Choosing a greenfield build turns 62 of the 106 objects into build-buy-or-drop decisions and makes the clean-core problem disappear into a requirements list.
  • Replaced the position bar chart with a treemap. A bar shows the split and hides the shape; it would tell you 51 objects carry forward without telling you that 33 of them are one decision and 18 another, resting on completely different evidence.
  • Added, then removed, an object inventory and a detail drawer. Built because “where is my object” is the first question anyone with a stake asks. Cut on the next read-through: a browsable list of 106 rows is precisely the artifact the eleven decisions exist to replace, and offering one beside them invites re-litigating the grouping one object at a time. The objects are still all there, inside the decision that funds them, where each one carries a reason.

On where the AI actually sits. Up to this point the AI story was entirely a negative claim — nothing is decided by a model — which proves judgement and shows no point of view. The assistant turns it positive without weakening it: the rules decide, a model explains, and everything the model wrote is labelled with what it was written from. The engine is unchanged; the number of model-written numbers on screen is still zero.
What I looked at and did not take. A parallel build of the same brief produced a risk matrix (business criticality against blast radius) and a much simpler per-object engine. The matrix was not ported: it restates fan-in and executions as a picture, and the decision modal already answers the same question with attribution and a named rule. The engine was not ported on principle — it calls 61 of 106 custom objects “decommission” on exec < 50 && users <= 2, which is precisely the confident, wrong retirement list the four-state evidence model exists to prevent. The headline sentence was worth taking, and was; the drawer was taken, used, and then cut for the reason above.
